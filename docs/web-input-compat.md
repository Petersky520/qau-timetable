# 教务网页直接输入兼容

同步页直接使用网页登录，不再提供额外的账号、密码、验证码输入框或「填入网页」。

`assets/web/login-input-compat.js` 在青农大域名的文档可见后安装，加载完成时再次幂等安装。
它维护输入框的最近选区，处理输入后异常回到零位置的情况；只有新值可以精确判定为错误的
前缀插入时才修正值。正常手动选区、未知编辑类型、页面格式化以及组词过程交还网页处理。
状态留在网页的 WeakMap 中，失焦后删除，不通过 JS 桥回传，也不写入日志或存储。

  中间插入、主动移到开头、选区替换、前后删除、无 data 的粘贴、中文组词及重复安装。
- 两变体各 287 项现有 JVM 单测通过。因本机 Gradle 测试启动器的类加载问题，使用其导出的
  runtime classpath 直接运行 JUnit；记录位于本机构建目录 `app/build/ui-review-*-junit.txt`。
- full/lite debug 与 release 构建通过，两个 release APK 中的脚本与被测试源文件逐字节一致。
- Android 模拟器内的真实教务登录页：账号、密码、验证码各自逐字输入虚构的 `12345`，
  模拟光标回零后继续输入，以及删除、中间插入、主动移到开头和选区替换，共 10 项通过。
  未提交登录，测试结束后清空输入。
- 独立 WebView 表单的 IME 组词提交验证通过。真实教务页的 CDP 中文组词测试在原始页面
  与兼容版均未保留前缀，因此不能据此宣称教务网页中文组词已经修复；本次目标为账号密码倒序。

## 验证边界

原问题手机的系统 WebView 与输入法组合尚未实测。模拟器的编辑命令和回零故障模拟不能
替代该手机的实际软键盘验证。应使用新包核对逐字输入、退格、粘贴和手动移动光标。
